# Internationalization

Checked against SillyTavern 1.19.0 (`public/scripts/i18n.js`). English text is the key and the
fallback; there is no English locale file.

## JS
```js
const { t, translate, getCurrentLocale, addLocaleData } = SillyTavern.getContext();
toastr.success(t`Saved ${count} notes`);   // key: "Saved ${0} notes"
translate('Show Gallery');                 // non-literal strings / explicit keys
```
- `t` keys keep `${0}`, `${1}` placeholders in order.
- `addLocaleData(locale, { key: translation })` only applies when `locale === getCurrentLocale()`,
  and **never overrides an existing key** (core's, or an earlier extension's).

## HTML
- `data-i18n="Key"` sets the element's **textContent** (replacing all children) - put it on a leaf
  `<span>`, never on a button that also contains an icon.
- `data-i18n="[title]Key"` sets an attribute; any attribute works (`[placeholder]`, `[aria-label]`).
- Several: `data-i18n="Text key;[title]Tooltip key"`. Keys cannot contain `;`; a key with `[word]` in
  it is misread as an attribute.
- Keep the English text in the element/attribute; it shows when no translation exists.
- Templates rendered with `renderExtensionTemplateAsync` are translated, and a document-wide observer
  translates any element with `data-i18n` inserted later, so dynamic HTML self-translates.

## Shipping translations
```json
"i18n": { "de-de": "i18n/de-de.json", "fr-fr": "i18n/fr-fr.json" }
```
- Only the file whose key **exactly equals** the current locale is fetched, before your JS runs, so
  top-level `t` calls see it. Errors are logged, never fatal.
- File = flat JSON `{ "English key": "Translation" }`.
- Core locale codes are lowercase `xx-yy`: `ar-sa zh-cn zh-tw nl-nl de-de fr-fr is-is it-it ja-jp
  ko-kr pt-pt ru-ru es-es uk-ua vi-vn th-th`. A browser reporting bare `de` gets no translation until
  the user picks a language.
- Because core keys win, a generic key such as `"Save"` uses core's translation - fine when the
  meaning matches; use full sentences or extension-specific wording otherwise.
- Debug: User Settings -> Debug menu -> "Get missing translations", "Apply locale".
