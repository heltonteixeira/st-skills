# 04 — Native-looking UI for ST UI extensions

Source: `dev-st` = SillyTavern 1.19.0 @ 06bde93. All paths relative to `dev-st/`. Docs = `research/st-docs/`.
"script.js" = `public/script.js`; other JS under `public/scripts/` unless stated. Line numbers are exact at this commit.
Statements marked **UNVERIFIED** were inferred, not traced end to end.

---

## 0. TL;DR rules
1. Mount settings into `#extensions_settings` (left column) or `#extensions_settings2` (right column) with the
   `inline-drawer` markup. ST does not pick the column for you (§1.1).
2. Use ST classes (`text_pole`, `menu_button`, `checkbox_label`, `flex-container`, ...) and `var(--SmartTheme*)` colors.
   Never hard-code colors, font sizes or durations.
3. Bind with delegated handlers (`$(document).on('click', '.myext_btn', ...)`) for anything per message or re-rendered.
4. Dialogs: `Popup` / `callGenericPopup` (popup.js). Feedback: `toastr`. Long tasks: `loader.show()` (action-loader.js).
   `callPopup`, `showLoader`/`hideLoader` and `renderExtensionTemplate` (sync) are deprecated.
5. Prefix every id and class with your extension name. Keep CSS selectors scoped. Avoid `!important`.

## 1. Where extensions put UI

### 1.1 Extensions panel (settings)
Markup, `public/index.html:5750-5808`:
```html
<div id="extensions-settings-button" class="drawer">
  <div class="drawer-toggle"><div class="drawer-icon fa-solid fa-cubes fa-fw closedIcon" ...></div></div>
  <div id="rm_extensions_block" class="drawer-content closedDrawer">
    <div class="extensions_block flex-container"> ...header row...
      <div id="extensions_settings" class="flex1 wide50p">
        <div id="assets_container" class="extension_container"></div> ... (16 reserved slots)
      </div>
      <div id="extensions_settings2" class="flex1 wide50p">
        <div id="websearch_container" class="extension_container"></div> ... (16 reserved slots)
      </div>
```
- **Who picks the column:** nobody. Each built-in and known extension has a hard-coded slot (`#sd_container`,
  `#summarize_container`, `#regex_container`, ...) at index.html:5773-5807. Built-ins append to their own slot:
  `$('#summarize_container').append(settingsHtml)` (extensions/memory/index.js:1069),
  `$('#regex_container')...` (regex/index.js:1729), `$('#vectors_container')...` (vectors/index.js:1743),
  `$('#translation_container')...` (translate/index.js:715). A third-party extension appends to `#extensions_settings` or
  `#extensions_settings2` itself. The docs example uses `#extensions_settings2` (Writing-Extensions.md:244). No balancing,
  no sorting of the DOM blocks.
- Load order: manifests sort by `loading_order` and then `display_name` (extensions.js:49,571). Because each extension
  appends during its own init, this order also roughly sets the order of the blocks in a column (**UNVERIFIED**: async init
  can race).
- Mobile: both columns are forced to full width (`css/mobile-styles.css:180-183`, inside `@media (max-width:1000px)`).
- Panel-scoped CSS you inherit: `.extensions_block input[type=checkbox|radio]{margin-left:10px;margin-right:10px}`
  (css/extensions-panel.css:10-13). The header gradient applies only to `#extensions_settings .inline-drawer-toggle.inline-drawer-header`
  and the `#extensions_settings2` equivalent (style.css:5403-5413). Outside the panel, add `.standoutHeader` to get the same look (style.css:5406-5423).

### 1.2 Wand / extensions menu (`#extensionsMenu`)

- `.extensionsMenuExtensionButton` is a 20×20 px centred icon with `pointer-events:none` (style.css:1120-1129), so a click

### 1.3 Top bar
- `#top-settings-holder` holds `.drawer` blocks (index.html:66-…). Each has `.drawer-toggle > .drawer-icon.fa-solid.fa-fw.closedIcon`
  and a `.drawer-content.closedDrawer` sibling (see 1.1).
- The toggle handler is bound **directly**, not delegated: `$('.drawer-toggle').on('click', doNavbarIconClick)` (script.js:12150).
  A drawer added later by an extension does **not** toggle on its own. You would have to import `doNavbarIconClick` from
  `script.js` (exported, script.js:10953; not in `getContext`). `.drawer-opener[data-target=<drawerId>]` is delegated (script.js:12148, 10939-10946).
- A `mousedown`/`touchstart` anywhere outside `.openDrawer` closes open drawers, unless the target is inside `.popup`,
  `.text_pole`, `#toast-container`, `.select2-results`, ... (script.js:12152-12190). Floating UI you attach to `body` from
  inside a drawer will close that drawer when clicked.
- No built-in extension adds a top-bar drawer. Treat it as non-standard.

```html
<div class="mes_buttons">

    <div title="Edit" class="mes_button mes_edit fa-solid fa-pencil " data-i18n="[title]Edit"></div>

```
- Built-ins hard-code their buttons in the template and attach **delegated** handlers:
  `$(document).on('click', '.mes_translate', onMessageTranslateClick)` (translate/index.js:753),
  `.sd_message_gen` (stable-diffusion/index.js:5039), `.mes_narrate` (tts/index.js:1567).
  The handler resolves the message with `$(this).closest('.mes').attr('mesid')` and then reads `context.chat[id]` (translate/index.js:673-674).
- Third-party pattern: append the button to the template once at init, so every newly rendered message clones it.
  `messageTemplate = $('#message_template .mes')` is a live reference, not a snapshot (script.js:448), and it is cloned in
  `updateMessageElement` (script.js:2618). Then bind one delegated handler. Messages already on screen do **not** get the
  button. Add it on `CHAT_CHANGED` or with `$('#chat .mes .extraMesButtons').append(...)` (**UNVERIFIED** as a documented convention).
```js
$('#message_template .mes_buttons .extraMesButtons').prepend(
  '<div title="My action" class="mes_button myext_msg_btn fa-solid fa-star" data-i18n="[title]My action"></div>');
$(document).on('click', '.myext_msg_btn', function () { const id = Number($(this).closest('.mes').attr('mesid')); ... });
```
- `.extraMesButtons` is `display:none` (style.css:4485-4487). The `…` hint shows it on click and hides it on any click
  elsewhere (script.js:11868-11930). With the user setting "Expand Message Actions", `body.expandMessageActions` shows
  them always (css/toggle-dependent.css:472-478). `.mes_button`: opacity .3, 1 on hover, `drop-shadow` (style.css:4489-4502).
  Children of `.extraMesButtons` without `.mes_button` are still made keyboard-interactable (keyboard.js:18).
- Per-message render hooks: `CHARACTER_MESSAGE_RENDERED(messageId, type)` (script.js:6693 etc.),
  `USER_MESSAGE_RENDERED(messageId)` (script.js:5912), `MORE_MESSAGES_LOADED` (script.js:1474), `CHAT_CHANGED` (script.js:1723).

### 1.7 Floating panels (`#movingDivs`, draggable)
- Container: `<div id="movingDivs">` (index.html:7737). CSS: `#movingDivs>div{z-index:4000}` (style.css:2977-2979).
  `.draggable` base: themed background, border and blur, `display:none`, `position:absolute` (style.css:5860-5879).
- Templates, index.html:6423-6442:
```html
<template id="generic_draggable_template">
    <div class="draggable">
        <div class="dragTitle"></div>
        <div class="panelControlBar flex-container">
            <div class="fa-fw fa-solid fa-grip drag-grabber"></div>

```
  `#zoomed_avatar_template` is a `.zoomed_avatar` with the same control bar. memory reuses it as a popout
  (memory/index.js:994-1012): it sets the id, removes `zoomed_avatar`, adds `draggable`, and uses the control bar
  `<div id="summaryExtensionPopoutheader" class="fa-solid fa-grip drag-grabber hoverglow">`.
- `dragElement($el)` (RossAscends-mods.js:477-) looks up the drag handle as `#${id}header` (line 487). The grabber **must** have
  id `<panelId>header` and class `drag-grabber` (mousedown check, ~line 627). Position and size persist in
  `power_user.movingUIState[id]` and emit `resizeUI` (lines 490-503). It does nothing on mobile or when MovingUI is off (line 522).
  Call `loadMovingUIState()` and then `dragElement(el)` after appending the panel (memory/index.js:1015,1017). Neither function is in `getContext()`:
  import `dragElement` from `RossAscends-mods.js` and `loadMovingUIState` from `power-user.js` (power-user.js:1835; memory imports it at memory/index.js:22).
- gallery's pattern: clone `generic_draggable_template`, make the id unique, set `closeButton.dataset.relatedId`, and
  handle close with a delegated `$('#movingDivs').on('click', '.dragClose', ...)` (gallery/index.js:32-40, 621-680).
- `.drag-grabber` shows only under `body.movingUI` (css/toggle-dependent.css:445-447) and is hidden on mobile
  (mobile-styles.css:361-365, `!important`). On mobile, `#movingDivs>div` becomes a full-width sheet under the top bar (mobile-styles.css:370-395).
- Open/close with `.fadeIn(animation_duration)` or `.transition({opacity, duration: animation_duration, easing: animation_easing})`
  (memory/index.js:1010, 1022), so reduced-motion is respected.

## 2. Settings drawer (inline-drawer)
Canonical markup, verbatim from `extensions/caption/settings.html:1-7` (identical in vectors/settings.html:1-7 and tts, sd, ...):
```html
<div class="caption_settings">
    <div class="inline-drawer">
        <div class="inline-drawer-toggle inline-drawer-header">
            <b data-i18n="Image Captioning">Image Captioning</b>
            <div class="inline-drawer-icon fa-solid fa-circle-chevron-down down"></div>
        </div>
        <div class="inline-drawer-content">
```
- Wiring is ST's job. A delegated `$(document).on('click', '.inline-drawer-toggle', …)` (script.js:12193-12215) finds
  `closest('.inline-drawer')`, toggles `down/up` and `fa-circle-chevron-down/-up` on `>.inline-drawer-header .inline-drawer-icon`,
  fires the jQuery event `inline-drawer-toggle` on the drawer, and `slideToggle`s `>.inline-drawer-content`. Clicks on a `.text_pole` inside the header are ignored.
  So the header needs **both** `inline-drawer-toggle` and `inline-drawer-header`, and the icon must be a direct child of the header.
- `.inline-drawer-content{display:none}` (style.css:5543-5545). It starts collapsed. To start open, add `style="display:block"` and the up-icon classes.
- Open or close from code: `toggleDrawer(drawerEl, expand)` (utils.js:2525-2558; no animation; dispatches `inline-drawer-toggle`, bubbling).
  React to toggles: `$(drawer).on('inline-drawer-toggle', …)` (pattern used at world-info.js:3532).
- Header extras: memory puts a popout button in the header, wrapped in `flex-container alignitemscenter margin0` (memory/settings.html:3-8).
- `.inline-drawer-maximize` with a `.floating_panel_maximize` icon toggles `.maximized` on the closest `.drawer-content` (script.js:12217-12224).
- Nested sub-drawers are fine (selectors use `>`).

- Buttons in ST are `<div class="menu_button">`, not `<button>`. They become keyboard-focusable and get `role=button` automatically (§6).
- Disable with the `.disabled` class or the `[disabled]` attribute: `.menu_button.disabled` greys out and sets `pointer-events:none` (style.css:3096-3102).
- `.menu_button.toggleable` / `.toggled` draws a ✓/✗ toggle button (style.css:3104-3135). `.red_button`/`.redWarningBG` is for destructive actions (style.css:3649-3657).
- Checkbox: `input[type=checkbox]` is fully restyled globally: themed box and tick color `--SmartThemeCheckboxTickColor` (style.css:4054-4093). Use it as is.
- There is no switch/toggle widget. Use a checkbox inside `.checkbox_label` (flex row, `column-gap:5px`, `align-items:baseline`; style.css:4596-4604).
- `<select>` is restyled globally with `/img/down-arrow.svg` (style.css:3046-3077). `textarea` is restyled globally (style.css:1547-1561).
  `textarea.autoSetHeight` grows with its content via `field-sizing:content` (style.css:1563-1566). ST resizes these when a drawer opens (script.js:12208-12213).
- **select2** is loaded globally (`index.html:8209`, `$.fn.select2`). Core uses it only on desktop:
  `if (!isMobile()) { $('#model_openrouter_select').select2({ placeholder, searchInputPlaceholder, searchInputCssClass:'text_pole', width:'100%', … }) }`
  (openai.js:7216-7224, horde.js:465, textgen-models.js:1419). Theming lives in css/select2-overrides.css. Helpers: `select2ModifyOptions`,
  `getSelect2OptionId` etc. (utils.js:2289-2390). No built-in extension uses select2.

  It sets `jQuery.fx.off`, sets `animation_duration` to 0 (and so `--animation-duration:0ms`), and adds `body.reduced-motion`.

## 5. Popups, toasts, loaders

### 5.1 `Popup` (public/scripts/popup.js), exposed as `getContext().Popup / POPUP_TYPE / POPUP_RESULT / callGenericPopup` (st-context.js:195,224-226)
- `POPUP_TYPE` (popup.js:9-20): `TEXT=1` (content + OK; Cancel only if `cancelButton` is set), `CONFIRM=2` (Yes/No),
  `INPUT=3` (textarea; OK shows as "Save"), `DISPLAY=4` (no buttons, only a corner ✕), `CROP=5` (cropper; resolves to a dataURL).
- `POPUP_RESULT` (popup.js:24-37): `AFFIRMATIVE=1`, `NEGATIVE=0`, `CANCELLED=null`, `CUSTOM1..9=1001..1009`.
- `new Popup(content, type, inputValue='', options)` (popup.js:194-219). `content` may be a string (set via `innerHTML`, **not sanitized**,
  popup.js:528-537), a jQuery object or an HTMLElement. Options (typedef popup.js:39-62; defaults in the constructor):
  `okButton`/`cancelButton` (string caption, or `true`/`false` to force show/hide), `rows`, `placeholder`, `tooltip`,
  `wide` (adds `.wide_dialogue_popup`, `min-width: var(--sheldWidth)`, style.css:3718-3723), `wider` (min-width 750px, max 90%; style.css:3725-3735),
  `large` (90vh × 90vw, style.css:3711-3716), `transparent`, `allowHorizontalScrolling`, `allowVerticalScrolling`, `leftAlign`,
  `animation` ('slow'|'fast'|'none'; **constructor default is `'fast'`** at popup.js:209, although the JSDoc says 'slow'),
  `defaultResult` (the button Enter triggers), `customButtons`, `customInputs`, `allowEscapeClose` (false ⇒ Escape needs a
  double-press plus confirmation, popup.js:561-608), `onClosing(popup)` (return falsy to cancel the close), `onClose(popup)`
  (after close, before DOM removal), `onOpen(popup)`, `cropAspect`, `cropImage`.
- `customButtons` (popup.js:287-321): `{text, result?, classes?, icon?: 'fa-…', tooltip?, action?, appendAtEnd?}` renders a
  `div.menu_button.popup-button-custom.result-control` placed before OK. No `result` ⇒ the button does not close the popup.
  Plain strings get results 2, 3, … .
- `customInputs` (popup.js:324-444): `{id, label, type:'checkbox'|'text'|'textarea'|'number', defaultState, tooltip, rows, min, max, step, disabled, autoFocus}`.
  Read them afterwards from `popup.inputResults.get(id)` (a Map, filled in `complete()`, popup.js:774-781).
- `await popup.show()` resolves to the value: for INPUT, the string on OK, `false` on No, `null` on cancel; otherwise the
  result number (popup.js:755-803). `popup.completeAffirmative()`, `completeNegative()` and `completeCancelled()` close it from code.
  `Popup.util.isPopupOpen()` and `Popup.util.lastResult` (popup.js:865-886).
- Helpers `Popup.show.input(header, text, default, opts)` → string|null; `Popup.show.confirm(header, text, opts)` → result;
  `Popup.show.text(header, text, opts)` (popup.js:98-144). The header and text are wrapped as `<h3>${header}</h3>${text}` (popup.js:896-902),
  as **raw HTML**. Built-ins escape user data first: `escapeHtml(url.href)` (extensions/assets/index.js:563).
- `callGenericPopup(content, type, inputValue, opts)` is just `new Popup(...).show()` (popup.js:914-922).
- Built-in form-in-popup pattern: render a template into a jQuery object, pre-fill it, `await callGenericPopup($el, POPUP_TYPE.CONFIRM, '', {okButton:t\`Save\`, cancelButton:t\`Cancel\`, allowVerticalScrolling:true})`,
  then read values from the still-referenced `$el` (regex/index.js:764-850).
- Inside a popup: Enter on a focused `.result-control` completes it (popup.js:628-662). Toasts are moved into the top `<dialog>`
  so they appear above it (`fixToastrForDialogs`, popup.js:939-971). Anything you float (dropdowns) should be appended to
  `Popup.util.getTopmostModalLayer()` (popup.js:930-934), not to `body`, or it ends up under the modal.
- Template: `#popup_template` (index.html:6469-6487). `dialog.popup > .popup-body > .popup-content / .popup-input / .popup-inputs / .popup-controls`.
- **Deprecated:** `callPopup` (script.js:9061-9067 `@deprecated Use callGenericPopup`; also flagged in st-context.js:193-194).

### 5.2 Toasts
- Global `toastr`. Defaults (script.js:348-366): `positionClass:'toast-top-center'` (user-configurable, power-user.js:1078),

## 8. HTML templates and sanitization
- `renderExtensionTemplateAsync(extensionName, templateId, data={}, sanitize=true, localize=true)` (extensions.js:137-139) fetches
  `scripts/extensions/${extensionName}/${templateId}.html` and compiles it with **Handlebars** (cached per path, templates.js:60-68).
  It then runs `DOMPurify.sanitize` and `applyLocale` (data-i18n) (templates.js:74-81). Third-party name: `'third-party/<folder>'` (Writing-Extensions.md:237-241).
  It returns `undefined` after a `toastr.error('Error rendering template')` on failure (templates.js:85-88).
  **Mismatch:** the JSDoc says "sanitation and localization is forced", but both are plain parameters (default true). The docs say "automatically sanitized", which is true only by default.
- Handlebars `{{x}}` escapes HTML. `{{{x}}}` does not. Because DOMPurify runs, inline `on*=` handlers and `<script>` in templates
  are stripped. Bind events in JS.
- The sync `renderExtensionTemplate` is deprecated (st-context.js:189-190) and uses a synchronous XHR (templates.js:15-26).
- Put templates next to `index.js`. Built-ins use `settings.html`, `button.html`, `dropdown.html`, `window.html`.
- i18n attributes: `data-i18n="key"` (text), `data-i18n="[title]key"`, several separated by `;`
  (e.g. `[placeholder]…`; index.html:6469, 8112). JS strings: `t\`…\``/`translate()` from getContext (st-context.js:214-217).
- User or model content: `messageFormatting(mes, ch_name, isSystem, isUser, messageId)` (script.js:1800; in getContext) runs
  showdown, then DOMPurify (script.js:1967). Use it to show chat-like text. For arbitrary strings use `SillyTavern.libs.DOMPurify.sanitize()`
  (lib.js:84-108) or set `textContent`/jQuery `.text()`. Popup content and `toastr(..., {escapeHtml:false})` are NOT sanitized.

## 10. Pitfalls
- **ID collisions:** everything shares one document with ~100 extensions. Prefix ids, classes, `name=` groups and template ids
  (`myext_…`). dragElement derives the handle id from the panel id (`${id}header`), and `movingUIState` is keyed by id. Docs: "Use unique module names" (Writing-Extensions.md:1426-1436).
- **CSS leakage and load order:** the manifest `css` is appended to `<head>` as `<link id="<name>-css">` **after** core CSS and
  `user.css` (extensions.js:781-805; index.html:36-46). Its equal-specificity rules beat core. The user's Custom CSS `<style id="custom-style">` is
  usually created earlier in `<head>` (power-user.js:1147-1156), so your rules may also beat the user's theme CSS (**UNVERIFIED** timing).
  Always scope rules (`.myext_settings .foo`, `#myext_panel …`). Never style bare `select`, `input`, `.menu_button`, `.mes`, `.drawer-content` globally.
- **`!important`:** core already uses it a lot (`displayNone`, margins, `neo-range-slider`, `body.no-blur * {backdrop-filter:unset !important}`).
  Adding more makes user themes impossible to override. Use `.toggleClass('displayNone')` instead of `.show()`, because `.show()` cannot beat `display:none !important`.
- **`hidden` vs `displayNone`:** `.hidden` is `visibility:hidden` and the element still takes space.
- **z-index layers** (style.css): `.draggable` 29, `#sheld`/`#form_sheld` 30, `.drag-grabber`/`.panelControlBar`/`.list-group` 2000,
  `#left-nav-panel` 3000, `#top-bar`/`#top-settings-holder` 3005, `#movingDivs>div` & `#floatingPrompt` 4000, `#shadow_popup`/
  `#dialogue_popup`/swipes 9999, autocomplete/jQuery-UI 10000, `#options`/`#extensionsMenu`/`.popup .popper-modal` 29999.
  `<dialog>` popups use the browser top layer, above everything. Pick values from this table; don't use `z-index:999999`.
- **Heavy per-message work:** `CHARACTER_MESSAGE_RENDERED`/`USER_MESSAGE_RENDERED` fire for every message, and streaming
  re-renders. Prefer template injection plus one delegated listener over per-message `.on()` binding or DOM rebuilds. Debounce
  (`debounce` in utils.js:574). Do not rewrite `.mes_text` innerHTML; use `updateMessageBlock` (getContext) or message-formatting hooks.
- **Drawer auto-close:** a mousedown outside `.openDrawer` closes the open drawer (script.js:12152-12190). Floating elements you
  add from inside the Extensions panel need to live inside it, or inside `.popup`.
- **Wand menu items:** use the `list-group-item` + `extensionsMenuExtensionButton` structure, or the row loses styling and keyboard access.
- **Re-init:** extensions can be re-enabled without reload (**UNVERIFIED**). Use `.off().on()` or guard with an "already mounted" check, as memory does (`$('#memory_restore').off('click').on(...)`, memory/index.js:1037-1040).
- **Docs vs source mismatches:** (1) Popup `animation` default is 'fast', not 'slow'. (2) `wide` is no longer 1:1 aspect (CSS commented
  out with a FIXME, style.css:3719-3721). (3) Template sanitize/localize are not forced. (4) The docs list POPUP options but omit `onOpen`,
  `transparent`, `leftAlign`, `animation`, `defaultResult`, `allowEscapeClose`, `tooltip` and `placeholder`. (5) `loader.hide()` without a handle hides
  every loader (not in docs). Otherwise the docs examples (Writing-Extensions.md:227-265, 1095-1237) match the source.
